W01

Agent 與研究 workflow

概念

本作沿用文件中的架構區分：固定的路徑和條件由程式管理；當模型根據研究狀況決定下一個查詢或工具時，才有動態 Agent 的部分。

研究用途

研究問題可以由模型協助澄清，但期間、成本、可用資料與工具權限應先明列。一次生成報酬說明，不等於已完成研究。

本作邊界

Wiki 與教材由本次 Codex 對話中的 LLM 節點整理；重跑指令執行的是可重現的程式 workflow，沒有藏在後端的即時 LLM。

為什麼這對量化研究重要

在本專案的量化研究中，問題澄清與內容解釋可以由 LLM 協助，候選比較、成本與時間切分則固定由程式執行。這樣能分辨「模型選了什麼」和「工具算了什麼」，追查錯誤時不必把整份研究當成黑箱。依 C01 的定義，本作的可重跑部分是 workflow；未來若讓模型根據結果選擇補查來源或停止研究，才需另外記錄那些動態決策。這是本作對來源概念的工程應用，不是來源替本作背書。

常見誤解

畫出流程圖、呼叫一次模型或讓程式依條件返回，都不能單憑名稱證明系統有自主性。反過來，固定 workflow 也不代表研究品質較差：若任務是重算同一份合成資料，固定輸入、工具與驗收條件反而方便比較。讀者應追問「下一步究竟由誰決定、決定的依據留在哪裡」，而非只看產品名稱是否含 Agent。
