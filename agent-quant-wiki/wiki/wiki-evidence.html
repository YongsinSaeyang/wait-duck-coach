W03

Wiki、主張與來源的對應

資料進入方式

七份資料都有本地章節整理和雜湊。Wiki 進一步按研究問題重組，連接概念、主張、相關頁和來源，而不是只列網址。S07 只讀摘要，其餘也保留實際讀取章節範圍。

查詢

教學大綱的問題先查 Wiki，產生 claim ID 和來源 ID 的 evidence pack。搜尋使用人工關鍵詞與字串比對，沒有 embedding 或向量庫。

語意邊界

程式可確認主張已登記、來源存在和雜湊一致；無法單靠 ID 判定文章真的支持一句話，仍需回原文核對。

為什麼這對量化研究重要

量化研究報告容易把文件規則、工程選擇與計算結果寫在同一段。本 Wiki 將它們分開：例如「固定路徑和動態 Agent 的差異」屬來源概念；「使用兩筆 gap」是本作設計；「主要測試零交易」是合成工具輸出。投影片先依問題取得 Wiki 與 claim，再沿來源定位或 runs 檔案回查，讓讀者知道一句話究竟依靠哪一種證據。這是 D01 的資料組織方法，不能當成原始文件提供的市場結論。

常見誤解

本地檔案有雜湊，只能證明正在讀同一份整理內容，不代表整理沒有理解錯。claim ID 存在也不能驗證引用的原文是否支持所有延伸推論。因此來源頁保留閱讀範圍，S07 明寫僅摘要；未知內容不自動補齊。Wiki 搜尋以詞彙與字串比對輔助瀏覽，教材的證據包則依明列 Wiki ID 路由，兩者都不是向量檢索。

研究含義為本專案的應用解釋；工程選擇與合成結果另標類型，不冒稱原文結論。
