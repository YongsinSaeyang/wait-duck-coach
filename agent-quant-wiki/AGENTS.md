# AI Agent 與量化研究 Wiki：開發與編輯規則

本專案是第十週的 LLM Wiki 與教學 HTML 簡報。讀者懂基本投資，尚需建立 Agent 架構與研究驗證的完整觀念。所有對外文字使用臺灣繁體中文，延續等等鴨的奶油白、深綠與杏色；簡報以大字、流程、原生表格和真實計算圖表教學，不把一頁塞成儀表板。

## 來源與 Wiki

- 先討論主題與深度，再擷取來源，最後才寫 Wiki／簡報。需求確認保留於 docs/discussion.md。
- 至少五篇原始資料實際讀取後，將相關章節的精簡整理放 content/sources/。不得只登記 URL。外部文章保留來源、定位、讀取範圍與日期；節錄整理不宣稱是完整全文快照。
- content/sources.json 登記七篇文件與本地整理檔的 SHA-256。精簡原文引用每來源最多 25 個英文單字；其餘以自己的話整理，保留引文與推論的界線。
- content/wiki/ 是由本次 Codex 對話中的 LLM 節點閱讀來源後整理的 Wiki。每篇有明確 claim ID、來源對應與相關頁。不是只把七張來源卡並排。
- content/claims.json 區分 source、design、synthetic 主張。來源主張要對到來源段落；工程設計要標本專案選擇；合成結果要對到可重算工具輸出。
- 模型在本次對話中協助作者整理與修改。Python 流程不私下呼叫 LLM；不得虛構 API、模型版本、token、延遲或自然失敗紀錄。

## 實驗與驗證

固定合成資料只有教學用途，不接券商、不送單、不宣稱真實市場績效。輸入 CSV、manifest、參數、逐筆交易與結果一起保存。選參數只看開發期的時間序列驗證；最終測試區間不回流選參數。資料時間和模型知識污染是不同風險，gap 不等於能消除 LLM 訓練污染。

原始資料與輸出都以雜湊追溯。日期、費用單位、訊號完成時間、成交時間和取位規則明列。故意錯誤案例要標 fault injection，不能稱為模型自然犯錯；真實資料取得失敗另列，不與案例混算。

## 流程與教材

workflow.json 記錄節點與退回條件；scripts/pipeline.py 以明列程式執行相同節點的可重跑查詢、檢查、工具計算與暫存建置。LLM 作者節點的輸出是 content/wiki/ 與 content/slides.json，修改前須閱讀 prompts/ 的工作說明。程式檢查不能取代來源語意的人工覆核。

每張投影片都要有 Wiki／claim／source 對應。教學由任務、Agent 定義、Wiki 證據、工具規格、時間切分、合成實驗、反思依序展開。滑動或鍵盤切換、目錄、閱讀模式、講者筆記及來源面板皆可操作。數字從工具輸出插入，不在投影片手抄第二套數值。

所有網站產物由 build.py 產生；不手改產生的 HTML。主張沒有來源、數字對不上、工具參數未定義或測試回流選參數時，停止輸出並回到對應節點。最多兩次修訂，仍未通過則交人工。

## 檔案

- content/sources.json、content/sources/*.md：本次讀取與 ingest 的資料。
- content/wiki/*.json、content/claims.json：Wiki 文章、可追溯主張。
- content/slides.json：18 頁教材結構與講者筆記。
- content/data/：合成資料與 manifest。
- workflow.json、runs/：流程定義與真的執行產生的紀錄。
- scripts/：標準庫的 ingest、查詢、驗證、研究工具、靜態建置。
- tests/：必要的失敗分支與計算驗證。
- index.html、slides.html、wiki/、sources/、evidence.html：可瀏覽產物。

建立 Wiki／教材前先跑來源檢查，最後跑完整檢查和瀏覽器預覽。更新紀錄只寫真的執行過的內容。網站發布狀態以實際工具回覆為準，不把 localhost 說成可供助教開啟的公開連結。
