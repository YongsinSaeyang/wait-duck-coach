等等鴨投資研究筆記庫的工作規則

這份文件適用於整個專案。開始修改前，先讀這份文件、README.md、content/sources.json，以及一篇現有筆記。若子目錄之後有更具體的規則，再一起遵守。

專案目的

替剛開始接觸量化投資的讀者整理可回查、可重做的研究筆記。每篇解決一個具體問題，例如沒有成交的 0% 報酬代表什麼。讀者可以從概念、教學計算和實作觀察理解研究限制。文字用繁體中文、像同學一起讀筆記，保留使用者真的提供過的經驗。

檔案與產出

  • 原始筆記放在 content/notes/YYYY-MM-DD-english-slug.md。
  • 所有外部資料來源登記在 content/sources.json，來源 ID 使用小寫英文與連字號。
  • 新筆記從 templates/note.md 複製，不能另造第二種格式。
  • 共用版面和 Markdown 轉換在 scripts/build.py。共用視覺在 assets/site.css，搜尋、分類、收藏及教學試算在 assets/site.js。
  • 執行 python3 scripts/build.py，產生根目錄 index.html、notes/slug.html 和 assets/notes.json。每篇筆記必須有自己的網址。
  • index.html 與 notes/*.html 是產物。修改內容時回到 Markdown，修改結構時回到建置程式，再重新產生。
  • 原始資料、模板、規則、建置程式和產物都需要提交到 GitHub。GitHub Pages 由 main 的根目錄發布，根目錄保留 .nojekyll。

每篇必須有的內容

檔案以兩條 --- 包住 JSON metadata。必填 id、title、date、updated、category、tags、summary、sources、related、origin。日期為 YYYY-MM-DD。id 必須與檔名的英文 slug 相同。

category 只能使用「量化入門」、「回測實作」、「研究方法」。tags 為 1–4 個不重複的短標籤。summary 30–120 個字。sources 列出登記過的來源 ID。related 列出 1–3 篇存在的筆記 ID，不能指向自己。origin 說明內容是作者提供的實測、程式推導，或公開文件整理。

正文依序包含四個二級標題，名稱保持一致。

  1. 我想釐清的問題
  2. 一個算得出來的例子
  3. 我會怎麼檢查
  4. 還需要注意什麼

正文可用三級標題、條列、表格、程式區塊，以及 [文字](https://官方頁面網址) 連結。每篇至少有一個可驗算的數字例子或可操作的檢查步驟。例子如為假設，當段就標明「教學假設」。日行情、績效和個人經驗不可自行補寫。

資料與引用

先讀來源再寫。優先引用官方文件和原始研究。新增來源要記錄 title、publisher、url、checked，checked 為實際讀取日期。來源頁未讀到相關內容時，標記待查並換用可確認的資料。

來源 ID 會在文章末尾自動產生來源卡。正文的關鍵敘述也應連到支持該敘述的官方頁面。筆記間的延伸閱讀用 related，網站會自動建立互相導覽。

財務計算用程式或明列公式驗算。單位、百分比、持有期間、成本和資料範圍要寫出來。百分比計算以小數進行，顯示時轉回百分數。0、負值和缺值分別處理。

公開內容以概念與教學假設為主。若使用者之後提供帳戶、金鑰或私人研究，先詢問哪些欄位可公開，再整理成可發布內容。

視覺與互動

奶油白背景、深綠文字、杏色重點，搭配小鴨引導。桌面保留導覽與閱讀欄，手機可自然換行。卡片統一顯示類別、日期、標題、摘要、標籤及閱讀連結。按鈕與連結需有清楚的鍵盤焦點，輸入框需有標籤。

每篇沿用同一文章模板，包含摘要、正文、來源、相關筆記與返回首頁。搜尋要涵蓋標題、摘要、標籤和正文。搜尋與分類可同時使用。收藏存於本機，失去本機儲存權限時仍能閱讀。

新增一篇的工作順序

  1. 讀規則、模板、來源登記及兩篇相關筆記。
  2. 確認使用者想解決的問題，整理已提供的觀察。缺少事實就寫待查或追問。
  3. 查證官方來源，更新 content/sources.json。
  4. 複製模板，填好 metadata 和四節正文，選擇相關筆記。
  5. 執行 python3 scripts/build.py，再執行 python3 scripts/check.py。
  6. 預覽新文章及首頁。檢查搜尋找到新文章、來源可點開、相關連結有效和手機版可讀。
  7. 在 CHANGELOG.md 記錄真的修改了什麼、跑過什麼檢查。沒有執行的測試應標為尚未測試。
  8. 一起提交原始 Markdown、登記資料和產物，等待 Pages 成功後確認正式頁面。

完成條件

新增文章可以只改內容與來源檔，沿用建置程式產生相同風格。發布前必須通過 schema、重複 ID、來源 ID、關聯 ID、必要段落、日期、內部檔案路徑與產物一致性檢查。若建置失敗，先修正來源，保留失敗訊息作為修改紀錄。尚未核實的網址、測試、部署結果不得寫成已完成。
